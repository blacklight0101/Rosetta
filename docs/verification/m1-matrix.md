## 2. Method

- **Tests.** The full Vitest suite ran locally on Windows against a disposable PostgreSQL 17 (`ROSETTA_TEST_DATABASE_URL`
  set, `--maxWorkers=2`): 7157 tests, 7136 passed, 0 failed, 21 skipped. The skipped ones are the Linux-only
  checks (container image, symbolic links on disk, POSIX shell steps and one signal test); they run in CI. The
  Playwright specs were listed (243 in `tests/e2e`, 6 in `tests/compose`) and pass in CI. CI on `main` at
  `6cb4d0e8` is green on every job: verify on Windows and Linux, the three e2e shards, the image job with Trivy, the
  Compose smoke test, `npm audit` and gitleaks (run 38528246211), and CodeQL (run 38528246193).
- **Requirement to test.** A test counts for a requirement when its name (or its `describe` title) carries the id,
  as conventions section 7 requires. The counts per level come from the Vitest JSON report and the Playwright list.
  One example per requirement is given; the full list is reproduced by `npm run test:levels` and a search for the id.
  Where the requirement's own _Verification_ line asks for a manual check, the check is listed with its state.
- **Threat model.** Each row of section 2 was traced to the code that implements its control and to the tests that
  prove it, and probed for bypasses by reading the code (findings below are confirmed in the code, not assumed).
- **RNF-014.** A second Compose stack (project `rosetta-p149`) was started from a copy of `.env.example` with only the
  empty local passwords filled; section 4.
- **RNF-003.** A full demo run (scan, understand of four areas, report, zip export) through the HTTP API of the real
  composition root with the end-to-end test doubles (fake GitHub, the recorded C# understand run), with planted fake
  secrets; section 5.

## 10. Proposed cards

For the orchestrator to file (README section 9). The three MAJOR findings each get a card; the MINOR findings are
grouped into three cards by kind. The matrix gaps already have cards (section 3.1). PC-01 and PC-03 add behaviour
the specification does not describe yet, so each starts with a spec question for the owner (ADR-010); the default
the card would apply is stated.

**PC-01 - Follow-up: bound the audit writes of refused requests** (F-01)

- **Difficulty**: 9 (opus). **Size**: M. **Refs**: RF-1009, RF-1100, RF-1109, RF-009, DEC-124, DEC-132, P1-49.
- **Do**: ask the owner (new Q; DEC-124 keeps every refusal row, so this changes it). Default: one limit per client
  address covers every refusal that writes a row (the `Origin` refusal, the route rate limits' `onExceeded`, the
  in-flight bounds of sign-in and password change, and any other `request.refused` writer): up to 30 rows a minute per
  address, then one `request.refused` row with reason `rate-limit` and a count for the rest of that minute, while the
  requests themselves are still refused with their usual status; the stored path (audit `target_id`, the security
  event's message and data) is cut to 512 characters with a marker that it was cut. Record the DEC. Write the failing
  tests first, then apply the limit and the cut where the row is written (`record-refused-request.ts` or a guard in
  front of it); update architecture section 10 and the threat model.
- **Done when**: 1,000 cross-origin POSTs from one address in a minute write at most 31 audit rows; 1,000
  same-origin `POST /api/session` requests from one address in a minute (past the rate limit and the in-flight bound)
  write at most 31 audit rows; a refused request with a 16 KB path stores at most 512 characters of it in the audit row
  and the log; a signed-in user's refusals below the limit still each write a row; the DEC row exists; `npm run verify`
  green.

**PC-02 - Follow-up: keep the migrator credentials out of the serving process** (F-02, F-19)

- **Difficulty**: 9 (opus). **Size**: M. **Refs**: RF-1302, RF-1305, ADR-014, ADR-016, P1-49.
- **Do**: run the migrations with `DATABASE_MIGRATOR_URL` in a one-off step (a `migrate` service or command in
  `compose.yaml`, the same in the P1-55 host procedure) that ends before the server starts, and start the server with
  `DATABASE_URL` only; the server refuses to start when it is given a migrator URL that is not needed, and warns when
  `DATABASE_URL` connects as the schema owner; if the change alters ADR-014 or ADR-016, write the amendment first
  (owner merge); add the residual risk to the threat model until it lands.
- **Done when**: the app container's environment holds no migrator password (`docker compose exec app env`); an
  integration test shows the credential the server holds cannot update or delete `audit_events` or `cost_ledger`;
  the Compose smoke test still passes; `npm run verify` green.

**PC-03 - Follow-up: refuse the placeholder secret key** (F-03)
