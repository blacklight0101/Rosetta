## 1. Choosing the project

The owner needed a final project for the Master en Desarrollo con IA: free topic and stack, individual, public
repository, first hand-in on 2026-10-26. Five candidate ideas were compared on usefulness, fun and fit with the
master's syllabus. Two were merged: an AI pipeline that understands a legacy codebase (idea 3) and a spec-first
project planner (idea 4) became one tool, Rosetta. A third idea, an energy-bill copilot, was kept as a possible
greenfield demo. Work code was excluded because the repository is public (DEC-03).

## 2. Shaping the solution

| Topic | Outcome | Why | Decisions |
|---|---|---|---|
| How agents run | An own agent loop in Rosetta's code, calling model APIs through one provider port | The owner wants to learn how agents work and to swap providers; a Claude-only SDK did not allow that | DEC-09, ADR-003 |
| Cost | Cost control inside the app: estimate, caps, live meter, price table, cost report | Paid APIs on a small budget; runs on different providers must be comparable | DEC-13, ADR-007 |
| Providers | Ollama first, OpenAI second, Anthropic later; model per role | Zero-cost development on local hardware, stronger models where quality matters | DEC-09, DEC-23 |
| Last stage | A tool-agnostic hand-off package; no rebuild | The team that takes the project builds it its own way | DEC-10 |
| Legacy stacks | Any stack: universal scan plus language packs | The tool must not be limited to one technology | DEC-11, ADR-004 |
| Demo target | Microsoft eShopLegacyWebForms (MIT) | Small, properly licensed, and Microsoft's modernised version serves as an answer key | DEC-12 |
| Trust | Evidence-cited cards and a two-step verifier | Hallucinations must be caught and measurable | DEC-18, DEC-19, ADR-005 |
| Privacy | Read-only agents; only requested, masked content leaves the machine | Users will analyse private code with secrets in it | DEC-16, DEC-17, ADR-006 |

## 3. Framing the build

| Topic | Outcome | Decisions |
